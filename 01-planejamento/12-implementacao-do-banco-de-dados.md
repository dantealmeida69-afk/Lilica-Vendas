# 12 implementacao do banco de dados

## 12.1 SGBD

O modelo físico abaixo usa SQL compatível com PostgreSQL. A estrutura segue as nove entidades da Entrega 2.

## 12.2 Script de criação (DDL)

```sql
CREATE TABLE usuario (
    id_usuario INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome VARCHAR(120) NOT NULL,
    email VARCHAR(160) NOT NULL UNIQUE,
    senha VARCHAR(255) NOT NULL
);

CREATE TABLE cliente (
    id_cliente INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome VARCHAR(120) NOT NULL,
    celular VARCHAR(20),
    email VARCHAR(160),
    observacoes VARCHAR(300)
);

CREATE TABLE produto (
    id_produto INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome VARCHAR(120) NOT NULL,
    valor DECIMAL(10,2) NOT NULL CHECK (valor >= 0),
    descricao TEXT
);

CREATE TABLE venda (
    id_venda INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    id_cliente INT NOT NULL REFERENCES cliente(id_cliente),
    id_usuario INT NOT NULL REFERENCES usuario(id_usuario),
    data_venda DATE NOT NULL,
    valor_total DECIMAL(10,2) NOT NULL CHECK (valor_total >= 0),
    status_pagamento VARCHAR(30) NOT NULL
);

CREATE TABLE item_venda (
    id_item_venda INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    id_venda INT NOT NULL REFERENCES venda(id_venda) ON DELETE CASCADE,
    id_produto INT NOT NULL REFERENCES produto(id_produto),
    quantidade INT NOT NULL CHECK (quantidade > 0),
    preco_unitario DECIMAL(10,2) NOT NULL CHECK (preco_unitario >= 0),
    subtotal DECIMAL(10,2) NOT NULL CHECK (subtotal >= 0),
    CHECK (subtotal = quantidade * preco_unitario)
);

CREATE TABLE pagamento (
    id_pagamento INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    id_venda INT NOT NULL REFERENCES venda(id_venda) ON DELETE CASCADE,
    data_pagamento DATE NOT NULL,
    valor_pago DECIMAL(10,2) NOT NULL CHECK (valor_pago > 0)
);

CREATE TABLE encomenda (
    id_encomenda INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    id_cliente INT NOT NULL REFERENCES cliente(id_cliente),
    id_produto INT NOT NULL REFERENCES produto(id_produto),
    quantidade INT NOT NULL CHECK (quantidade > 0),
    data_encomenda DATE NOT NULL,
    status VARCHAR(30) NOT NULL
);

CREATE TABLE fornecedor (
    id_fornecedor INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome VARCHAR(120) NOT NULL,
    telefone VARCHAR(20),
    email VARCHAR(160)
);

CREATE TABLE repasse (
    id_repasse INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    id_fornecedor INT NOT NULL REFERENCES fornecedor(id_fornecedor),
    valor DECIMAL(10,2) NOT NULL CHECK (valor >= 0),
    data_repasse DATE NOT NULL,
    observacao VARCHAR(300)
);
```

## 12.3 Índices sugeridos

```sql
CREATE INDEX idx_venda_cliente ON venda(id_cliente);
CREATE INDEX idx_venda_usuario ON venda(id_usuario);
CREATE INDEX idx_item_venda_venda ON item_venda(id_venda);
CREATE INDEX idx_item_venda_produto ON item_venda(id_produto);
CREATE INDEX idx_pagamento_venda ON pagamento(id_venda);
CREATE INDEX idx_encomenda_cliente ON encomenda(id_cliente);
CREATE INDEX idx_encomenda_produto ON encomenda(id_produto);
CREATE INDEX idx_repasse_fornecedor ON repasse(id_fornecedor);
```

## 12.4 Integridade

As chaves estrangeiras impedem referências a registros inexistentes. As restrições `CHECK` impedem quantidades inválidas, valores negativos e subtotais incompatíveis com quantidade × preço unitário.
